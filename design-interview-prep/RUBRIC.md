# Scoring & Debrief

## Dimensions

Scored using Twilio's own CDF competency categories (CONTEXT.md) rather than an invented taxonomy, so the debrief lines up with how the user's org actually talks about levels. Score each Strong / Adequate / Weak / Red Flag, calibrated to the selected level's bar:

- **Product strategy** — business/market reasoning, metrics fluency, using customer and business context to justify a decision (not just describe one)
- **Teamwork & communication** — communication under pressure, the required PM/Engineering working-relationship answer, cross-functional and generalist range
- **Craft & execution** — design decisiveness, the AI-can't-replicate-this signal, and the required tool-fluency answers (Claude Code, Git/GitHub, Storybook)
- **Leadership & influence** — navigating conflict, mentorship/upleveling others, driving a decision through an org, hiring/team-health signals (IC candidates are scored on this lightly at Entry/Senior, heavily at Staff+; Management-track candidates are scored on this as the primary dimension)

## Debrief template

Produce exactly this structure at wrap-up, regardless of visibility mode:

```
## Interview Debrief — [level/track] · [company size] · [B2B/B2C] · [competitiveness] · [format(s) run]

**Per-question notes:**
1. [question] → Tier [n] → [rating] → [one-line why]
2. [question] → Tier [n] → [rating] → [one-line why]
   ...

**Calibrated level reached:** [e.g. "Tier 3 — one rung above Staff" or "Ceiling+ — beyond Director"]
[1-2 line trajectory, e.g. "Started at the Staff baseline, climbed toward Principal on the
metrics question, then dropped back once the leadership follow-up exposed a gap."]

**CDF competency scores:**
- Product strategy: [rating]
- Teamwork & communication: [rating]
- Craft & execution: [rating]
- Leadership & influence: [rating]

**Required-question notes:**
- PM/Engineering working relationship: [one-line read — specific and honest, or generic and rehearsed?]
- Tool fluency (Claude Code / Git-GitHub / Storybook): [one-line read per tool — real specific example, vague familiarity claim, or honest "haven't used it"?]

**Strongest moment:** [specific, quoted or closely paraphrased]

**Biggest red flag:** [specific — or "none" if genuinely none occurred]

**What a hiring committee would write:** [2-3 sentences in the terse, slightly
clinical register of real hiring-committee notes, referencing the specific level bar from CONTEXT.md]

**Overall lean:** Strong Hire / Hire / Leaning No / No Hire

**Model rewrite of your weakest answer:**
[Rewrite the candidate's weakest response as an answer that actually clears the selected
level's bar would sound — concrete decision, real number, honest tradeoff, generalist framing
scaled to that level. Keep it grounded in what they actually described; don't invent a
different project.]
```

## Rules for writing the debrief

- Never inflate ratings to be encouraging, regardless of which tone (CONTEXT.md) the session ran in. If the session was mostly Weak/Red Flag, the overall lean should say so plainly — a Supportive Coach session can frame the debrief's delivery more gently, but every rating and the overall lean must be identical to what a Brutal-tone run of the same transcript would produce.
- Calibrate every rating to the *selected* level's bar (CONTEXT.md), not a generic "good designer" bar — an Entry-level answer that would be Weak for a Principal candidate can be Strong for Entry.
- The "model rewrite" must reuse the candidate's actual project/scenario — don't substitute a generic example. The value is showing them the stronger version of *their* answer.
- Keep "what a hiring committee would write" in the terse, slightly bureaucratic register real committees actually use — not motivational-coach language.
