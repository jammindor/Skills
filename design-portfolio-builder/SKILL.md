# Design Portfolio Builder

Turn partial, messy, or nonexistent material into an interview-ready case study — in two phases, in one session. Companion to `design-interview-prep`: that skill pressure-tests a story once it exists; this one builds the story.

Read [CONTEXT.md](CONTEXT.md), [DISCOVERY.md](DISCOVERY.md), [FRAMEWORK.md](FRAMEWORK.md), and [AUDIT.md](AUDIT.md) before running a session — they hold the level/company/tone dials, the intake-and-gap-filling technique, the case-study structure, and the scoring rubric this file orchestrates.

## Session flow

1. **Open, briefly and tone-neutrally.** One or two sentences that this is a two-phase working session — discovery first, then drafting — not a one-shot writing request. Don't commit to a voice yet; tone hasn't been picked.

2. **Ask the setup questions, plainly, in one message** (conversational, not AskUserQuestion — this is an intake, not a form). If the user's opening message already answered some of these, don't re-ask them verbatim — acknowledge what you heard and only ask for what's still missing:
   - **Tone** (CONTEXT.md): **Brutal**, **Professional** (default if no preference expressed), or **Supportive Coach**. Lead with this one — it sets the voice for everything that follows.
   - **Level & track** (CONTEXT.md): IC — Entry / Senior / Staff / Principal — or Management — Associate Manager / Manager / Senior Manager / Director / Senior Director.
   - **Target company**: size (solo/small startup, Series B-D department, enterprise UX org), B2B or B2C, and market competitiveness. If what the user describes doesn't map cleanly onto CONTEXT.md's three size buckets (e.g. "mid-size startup"), say which bucket you're treating it as and why, rather than silently picking one.
   - **Scope**: one case study deep-dive, or a full portfolio (typically 3-4 case studies — see FRAMEWORK.md's "Portfolio-level architecture" section).
   - **What already exists** for this project — a rough draft, an old case study, resume bullets, docs/decks, screenshots, or nothing written down yet. Ask them to paste or describe whatever they have; don't assume a blank page.

3. **Hold the selected tone for the rest of the session**, alongside the level/company dials — it voices every line from here on (CONTEXT.md/DISCOVERY.md), but never changes what gets flagged, triaged, or scored.

4. **Deliver a short opening acknowledgment now, in the selected tone**, before starting Phase A — e.g. Professional: plain and direct about what you heard and what's next; Brutal: the same, blunter, no cushioning; Supportive Coach: explicitly frame this as safe, collaborative working session. Keep it to a sentence or two and move on.

5. **Run Phase A — Discovery/intake** (DISCOVERY.md), voiced in the selected tone, one project at a time:
   - Absorb any supplied material fully before asking anything.
   - Triage each skeleton section (FRAMEWORK.md) as usable as-is / needs modification / missing entirely, and state the triage back to the user in one short pass.
   - Ask targeted questions, one at a time, to fill what's thin or missing — don't interrogate with a list.
   - Name the single biggest gap out loud before moving to Phase B, calibrated to the target level, in whatever register the tone calls for.
   - If building a full portfolio, repeat this phase per project before moving any of them into Phase B, so project selection (which stories to keep, which to cut) happens with full information.

6. **Run Phase B — Build** (FRAMEWORK.md), voiced in the selected tone, section by section:
   - For each section, state whether this is a tightening pass, a reframe, or a rebuild (FRAMEWORK.md's "working from existing material"), then draft it.
   - Show one section at a time and take feedback before moving to the next — never dump a full case study unreviewed.
   - Calibrate scope and what counts as strong evidence using the level/company dials from CONTEXT.md.
   - Handle any unmeasured-outcome or missing-rejected-alternative gaps per FRAMEWORK.md rather than writing around them vaguely.

7. **Wrap up** with the AUDIT.md scorecard for the finished case study (or each one, if multiple), and suggest running `/design-interview-prep` in portfolio-review format as the natural next step.

8. **Never inflate the scorecard, in any tone.** No softening beyond what the material actually earned, whether the session ran Brutal or Supportive Coach — see AUDIT.md's tone invariant.

## Notes

- This is coaching, not an adversarial interview, in every tone — warm and specific about what's working, direct about what's missing, per DISCOVERY.md's tone guidance.
- The selected tone stays constant for the whole session — don't drift voice mid-session even as material improves or a gap turns out to be worse than expected; only the substance of what's said scales with the work, not the register it's said in.
- Never let a flagged gap (missing number, missing rejected-alternative, dodged retrospective) silently disappear into the final draft — either fill it, or carry it forward explicitly as an open risk in the wrap-up.
- Don't draft speculative content the user never confirmed — everything in the final copy should trace back to something they actually said, even when it's substantially reframed.
- If the user only wants a quick single-section fix rather than a full session ("tighten this up"), it's fine to skip straight to a lightweight version of Phase B for that section — but still run the AUDIT.md triage on it first, and still name any Red Flag or missing-entirely gap out loud before touching the copy. "Quick" shortens the session, it never means a real gap (missing number, missing rejected alternative, dodged retrospective) gets polished over unflagged.
